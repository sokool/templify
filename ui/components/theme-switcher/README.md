# Theme switcher

HTML-first theme selection using a labelled native select. The source template
lists the built-in Light, Dark and Matrix themes. Applications can render their
own options with IDs matching their `[data-ds-theme]` CSS rules.

## Workspace

```js
const view = DesignSystemThemeSwitcher.mount(element, { themes });
view.select('dark');
view.destroy();
```

The shared themes service supplies the list, current theme, subscriptions and
persistence. Added, copied, removed and imported themes update every mounted
switcher. The workspace uses the same component for the sidebar cycle button
(`data-theme-next`) and the selectors on the Theme pages.

On **Components → Theme switcher**, **Show in menu footer** controls whether the
workspace mounts the cycle button at the bottom of Navigation (enabled by default).
The choice is saved as `components.theme-switcher.menuFooter` in workspace settings
and included in template JSON. Turning it off destroys and removes only that button;
page selectors and the selected theme remain unchanged. Footer placement belongs
to the host composition, not the standalone component.

A complete theme contains colours, shadows, typography (`fontFamily`) and icon
presentation (`iconSize`, `iconStroke`). Edit typography and icons through
`themes.setAppearance(themeId, values)`. Copies retain these settings; reset
restores defaults. CSS and token JSON exports retain them too. Existing global
font preferences migrate without overwriting theme-specific settings.

## Keyboard shortcut and Search

The shared Shortcuts catalogue registers `theme-switcher.nextTheme` (**Next theme**)
with default **Cmd/Ctrl+Shift+L**. It cycles through the available themes but is
not listed in Search.

Search instead lists **Theme: Light**, **Theme: Dark**, **Theme: Matrix** and each
custom theme by its own name. These actions use stable
`theme-switcher.selectTheme.[id]` identifiers (also available through
`themeActionId(id)`), have no default key binding and call the same `select(id)`
handler as the component. Added, renamed and removed themes update the catalogue.
Actions are unavailable with fewer than two themes. Removing the cycle binding
does not remove these specific theme choices from Search.

On **Components → Theme switcher**, record or reset the binding in **Keyboard
shortcut**, or edit the same action on **Components → Shortcuts**. The workspace
retains the command across pages, even when **Show in menu footer** is off.
Shortcut preferences use the existing per-theme Shortcuts persistence.

Declare another default without application JavaScript:

```html
<label class="theme-switcher" data-ui="theme-switcher" data-theme-shortcut="Mod+J">
  <span>Theme</span>
  <select data-theme-select aria-label="Theme">
    <option value="light">Light</option>
    <option value="dark">Dark</option>
  </select>
</label>
```

Omitting `data-theme-shortcut` uses `Mod+Shift+L`; an empty value or `false`
declares no binding. Live attribute changes update the default, but saved user
preferences always take precedence. Multiple switchers share the same actions; the
first mounted owner supplies its default. Destruction releases that owner and
unregisters the actions when the last owner is destroyed.

Load `shortcuts.js` before `theme-switcher.js` in classic-script applications.
Hosts can retain the action without a visual control using
`DesignSystemThemeSwitcher.create({ document, themes, shortcuts })`; its
`select(id)`, `next()` and `destroy()` methods share the component behavior.

## Export

The exported client initialises `data-ui="theme-switcher"` automatically and
sets `data-ds-theme`, `data-ds-theme-base` and `data-theme` on the document root.
All switchers follow that root, including changes made by the application.
Selection emits `ui:theme-change` with `event.detail.theme`. The native select
retains its keyboard support; the shared catalogue handles the global shortcut
without requiring the Shortcuts editor or Search component to be displayed.

Supply your theme CSS (including the CSS generated by `themes.exportCSS()`),
render corresponding options and deliver the required fonts in your application.
The standalone component does not include workspace settings, the Theme editors
or font downloads, and does not persist a selection by itself.

HTMX cleanup and `Templify.destroy()` remove handlers and observers. Repeated
initialisation of the same root reuses its existing instance.
